# Deploying to Render

`render.yaml`, at the git repo root (one level above this `egx-n8n-scanner`
folder — Render's Blueprint scanner only looks at the repo root, never a
subdirectory), is a Render Blueprint that provisions four things: a managed
Postgres database (`egx-postgres`), the n8n workflow engine (`egx-n8n`, the
stock n8n image, paid plan + persistent disk so credentials/workflows
survive redeploys), a one-shot DB restore job (`egx-db-init`), and the
static dashboard (`egx-webapp`). Each service sets `rootDir:
egx-n8n-scanner` so their build context (Dockerfile, `sql/`, `data/`,
`webapp/`, etc.) still resolves correctly from that subfolder.

`egx-n8n` uses the unmodified `n8nio/n8n` image directly — it's a
"hardened" Alpine build with no package manager, so it can't be customized
in-place (no `psql`, no custom start script). `N8N_HOST`/`WEBHOOK_URL` are
therefore hardcoded to Render's predictable default domain
(`https://egx-n8n.onrender.com`) rather than derived at runtime — if you
rename the `egx-n8n` service or attach a custom domain, update the
`N8N_HOST`/`WEBHOOK_URL` env vars on `egx-n8n` AND `N8N_BASE_URL` on
`egx-webapp` to match.

## 1. Push to GitHub

Push the repo (both `render.yaml` at the root and this `egx-n8n-scanner`
folder) to GitHub as-is — no Root Directory setting needed in Render, since
`render.yaml` is already at the true repo root.

`.env` is git-ignored on purpose — never commit real secrets.

## 2. Create the Blueprint in Render

Render dashboard -> **New +** -> **Blueprint** -> pick the repo -> Render
finds `render.yaml` at the root and shows the resources it's about to
create -> **Apply**.

You'll be prompted for the two env vars marked `sync: false` in
`render.yaml` (real secrets, not committed):

- `MARKET_API_BASE_URL` — your EODHD (or other provider) API base URL
- `MARKET_API_KEY` — your EODHD API key

Everything else (Postgres password, `N8N_ENCRYPTION_KEY`,
`REPORT_WEBHOOK_SECRET`, n8n basic-auth password) is auto-generated by
Render per `generateValue: true`.

## 3. Restore the data (one manual click)

Cron jobs on Render don't run automatically on deploy — go to the
**egx-db-init** service in Render's dashboard and click **Trigger Run**
once. It restores `data/full_dump.sql.gz` — the full schema plus ~10
months of already-imported real EGX data (241 stocks, daily prices,
technical analysis, scan history, backtest results) — into the fresh
database. Idempotent: safe to trigger again later, it just checks for the
existing schema and no-ops.

(`egx-db-init` uses its own small image based on plain `postgres:16-alpine`
— NOT `egx-n8n`'s image — specifically because that one lacks a package
manager to install `psql` into.)

## 4. Manual one-time steps in n8n (same as local docker-compose — see
   `docs/IMPORT-N8N.md`)

n8n's Postgres node credentials and workflow imports are deliberately not
pre-wired (security — see `docs/IMPORT-N8N.md`, "Why credentials can't ship
pre-wired"). After step 3 above:

1. Open the `egx-n8n` service URL, create the n8n owner account.
2. **Credentials -> New -> Postgres.** Render's dashboard (`egx-postgres` ->
   Info tab) shows the host/port/database/user/password to enter — these
   are also exposed as `POSTGRES_HOST` / `POSTGRES_PORT` / `POSTGRES_DB` /
   `POSTGRES_USER` / `POSTGRES_PASSWORD` in `egx-n8n`'s Environment tab if
   you'd rather copy them from there.
3. Import all 15 `workflows/*.json` files, assign that Postgres credential
   to every Postgres node (`docs/IMPORT-N8N.md` has the exact steps).
4. Publish workflows in dependency order: `01`, `03`-`11`, then `12`, `13`,
   `14`, `15` (Execute Workflow nodes can only call published
   sub-workflows).
5. Activate `03`, `12`, `14` so their schedules go live. Default schedule
   (Africa/Cairo, Sun-Thu): `03` retries every 30 min 16:00-20:30 to catch
   EODHD's variable EOD publish lag, `12` (full scan) runs once at 21:00,
   `14` (evaluation) at 22:30 — see README.md "Running the scanner" for why.

## 5. Verify

- `egx-webapp`'s URL should load the dashboard and show data immediately
  (from the restored dump, once step 3 is done) without any Settings
  configuration — the base URL and Report API are already wired up.
- If you want a fresh live scan instead of relying on the bundled dump,
  open `12 - EGX Daily Master Workflow` in n8n and click its Manual Trigger.

## Costs

This Blueprint uses paid plans for `egx-postgres` (`basic-256mb` — Render's
smallest current persistent Postgres tier; legacy names like `starter` are
no longer available for new databases), `egx-n8n`, and `egx-db-init` (both
`starter`, the service-plan naming, which is separate from database
instance types) specifically so the database persists past Render's 30-day
free-Postgres expiry and n8n's disk survives redeploys —
Render doesn't attach persistent disks to free-tier services at all, and
n8n needs one to keep its encryption key / imported workflows / credentials
across restarts. `egx-webapp` (static site) is free. Downgrade the `plan:`
fields in `render.yaml` if you'd rather accept those tradeoffs (workflows
stay safe in Postgres either way, but you'd need to re-create the n8n owner
account and re-import workflows after every restart on the free tier).
