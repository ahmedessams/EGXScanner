# Deploying to Render

`render.yaml` (repo root of this folder) is a Render Blueprint that
provisions three things: a managed Postgres database (`egx-postgres`), the
n8n workflow engine (`egx-n8n`, Docker-based, paid plan + persistent disk so
credentials/workflows survive redeploys), and the static dashboard
(`egx-webapp`).

## 1. Push to GitHub

Push this folder to the GitHub repo you'll import into Render. If your
GitHub repo root IS this `egx-n8n-scanner` folder, push as-is. If this folder
is a subdirectory of a larger repo, note the path — Render's Blueprint setup
asks for a "Root Directory" and `render.yaml` needs to be found there.

`.env` is git-ignored on purpose — never commit real secrets.

## 2. Create the Blueprint in Render

Render dashboard -> **New +** -> **Blueprint** -> pick the repo (set the Root
Directory if needed, per above) -> Render reads `render.yaml` and shows the
three resources it's about to create -> **Apply**.

You'll be prompted for the two env vars marked `sync: false` in
`render.yaml` (real secrets, not committed):

- `MARKET_API_BASE_URL` — your EODHD (or other provider) API base URL
- `MARKET_API_KEY` — your EODHD API key

Everything else (Postgres password, `N8N_ENCRYPTION_KEY`,
`REPORT_WEBHOOK_SECRET`, n8n basic-auth password) is auto-generated by
Render per `generateValue: true`.

## 3. First deploy: what happens automatically

- `egx-postgres` is provisioned empty.
- `egx-n8n` builds from `Dockerfile.n8n` (adds a Postgres client to the
  stock n8n image), then its `preDeployCommand` runs
  `scripts/render-db-init.sh`, which restores `data/full_dump.sql.gz` — the
  full schema plus ~10 months of already-imported real EGX data (241
  stocks, daily prices, technical analysis, scan history, backtest results)
  — into the fresh database. This only happens once; later deploys detect
  the existing schema and skip it (a fast no-op check).
- `egx-webapp` builds as a static site; its build step substitutes the real
  `egx-n8n` URL into the dashboard so it points at the right API with zero
  manual config.

## 4. Manual one-time steps (same as local docker-compose — see
   `docs/IMPORT-N8N.md`)

n8n's Postgres node credentials and workflow imports are deliberately not
pre-wired (security — see `docs/IMPORT-N8N.md`, "Why credentials can't ship
pre-wired"). After the Blueprint finishes deploying:

1. Open the `egx-n8n` service URL, create the n8n owner account.
2. **Credentials -> New -> Postgres.** Render's dashboard (`egx-postgres` ->
   Info tab) shows the host/port/database/user/password to enter — these
   are also exposed as `POSTGRES_HOST` / `POSTGRES_PORT` / `POSTGRES_DB` /
   `POSTGRES_USER` / `POSTGRES_PASSWORD` in `egx-n8n`'s Environment tab if
   you'd rather copy them from there.
3. Import all 15 `workflows/*.json` files, assign that Postgres credential
   to every Postgres node (`docs/IMPORT-N8N.md` has the exact steps).
4. Publish workflows in dependency order: `01`, `03`-`11`, then `12`, `13`,
   `14`, `15` (Execute Workflow nodes can only call published
   sub-workflows).
5. Activate `03`, `12`, `14` so their schedules go live. Default schedule
   (Africa/Cairo, Sun-Thu): `03` retries every 30 min 16:00-20:30 to catch
   EODHD's variable EOD publish lag, `12` (full scan) runs once at 21:00,
   `14` (evaluation) at 22:30 — see README.md "Running the scanner" for why.

## 5. Verify

- `egx-webapp`'s URL should load the dashboard and show data immediately
  (from the restored dump) without any Settings configuration — the base
  URL and Report API are already wired up.
- If you want a fresh live scan instead of relying on the bundled dump,
  open `12 - EGX Daily Master Workflow` in n8n and click its Manual Trigger.

## Costs

This Blueprint uses paid plans for `egx-postgres` and `egx-n8n` (the
`starter` plan) specifically so the database persists past Render's 30-day
free-Postgres expiry and n8n's disk survives redeploys — Render doesn't
attach persistent disks to free-tier services at all, and n8n needs one to
keep its encryption key / imported workflows / credentials across restarts.
`egx-webapp` (static site) is free. Downgrade the `plan:` fields in
`render.yaml` if you'd rather accept those tradeoffs (workflows stay safe in
Postgres either way, but you'd need to re-create the n8n owner account and
re-import workflows after every restart on the free tier).
